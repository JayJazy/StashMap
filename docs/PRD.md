# StashMap — 제품 요구사항 명세서 (PRD)

> **목적**: 이 문서는 StashMap 앱의 화면/플로우 디자인을 위한 기준 문서입니다.
> 기존 디자인 시스템(색상·타이포·컴포넌트)과 일관된 화면 설계를 목표로 합니다.
> **작성 기준일**: 2026-05-31

---

## 1. 한 줄 정의

> **StashMap = 리뷰 조작 시대의, 조작 없는 "정직한 내 맛집 다이어리" + 가벼운 발견 소셜**

---

## 2. 문제 정의 & 핵심 가설

- **문제**: 리뷰 이벤트·대가성 리뷰 때문에 별점/리뷰의 신뢰도가 무너졌다. 4.5점이 진짜인지 알 수 없다.
- **가설**: 사람들은 **"이 사람이 *다시 갈* 집인가"** 라는 행동 신호를 더 믿는다.
- **해법**: 별점 5점제를 버리고 **"다시 먹을래요 / 보통이에요 / 다신 안 먹을래요"** 라는 **행동 기반 평가**로 바꾼다.
  거짓말하기 어렵고, 직관적이며, 조작의 의미가 없어진다.

> 별점은 "이 집 4.2점"이지만, StashMap은 **"100명 중 78명이 다시 가겠다고 함"** 을 보여준다.
> → 이 약속은 **6.6 가게 집계 페이지**(여러 사람 평가 합산)에서 실제로 구현된다.

---

## 3. 타깃 사용자

- **한국 전용** 서비스 (지도·장소 데이터는 **카카오** 기반). 광고/마케팅도 한국 타깃.
  - 앱 다국어(한/영)는 코드상 지원되나, 1차 타깃 언어는 **한국어**.
- 맛집을 기록·관리하고 싶은 개인 (1차: 나만의 다이어리).
- 조작 없는 진짜 평가를 보고 싶은 탐색 사용자 (2차: 발견).

---

## 4. 핵심 평가 체계 (가장 중요한 디자인 요소)

총 **4개의 상태**. 단, 성격이 둘로 나뉜다.

| 상태 | 한국어 | 영어 | 성격 | 색 방향(새 시스템에서 확정) |
|---|---|---|---|---|
| 😍 | 다시 먹을래요 | Favorite | 방문 후 평가 (긍정) | 긍정 계열 (예: 그린) |
| 😐 | 보통이에요 | Average | 방문 후 평가 (중립) | 중립 계열 (예: 옐로/오렌지) |
| 🙅 | 다신 안 먹을래요 | Avoid | 방문 후 평가 (부정) | 부정 계열 (예: 레드) |
| 🔖 | 먹어보고 싶어요 | Want to try | **방문 전 (위시리스트)** | 정보/기대 계열 (예: 블루/브랜드색) |

### 핵심 메커니즘
- 앞 3개는 **먹어본 뒤** 매기는 평가다.
- "먹어보고 싶어요"는 **먹기 전 상태 = 위시리스트**다. 별도로 관리한다.
- **전환 흐름**: 위시리스트 항목을 **"방문 완료"** 처리하면 → 3단계 평가 중 하나로 전환된다 (이때 방문일·사진·메모 등을 추가).
- **단, 통계 화면(2x2 그리드)에서는 4개 모두 개수를 표시한다.** (위시리스트도 하나의 칸으로 보임)

> 디자이너 참고: 이 4개 상태는 앱 전체에서 **색/아이콘이 일관되게** 반복되어야 합니다. 일종의 미니 브랜드 시스템처럼 다뤄주세요.

## 5. 정보 구조 (IA) — 바텀 네비 3탭

기존 구현된 바텀 네비를 그대로 사용:

```
┌─────────────────────────────────────────┐
│  Home (탐색)  │  맛집 (내 기록)  │  프로필 │
└─────────────────────────────────────────┘
```

| 탭 | 역할 | Phase |
|---|---|---|
| **Home** | (Phase 1) 개인 대시보드 → (Phase 2) 다른 사람 공개 기록 탐색 | Phase 1 & 2 |
| **맛집 (Stash)** | 내가 등록한 가게 리스트 + 통계 + 위시리스트 | Phase 1 |
| **프로필** | 활동 통계·설정 (언어/테마/정보/문의) — **재디자인 대상** | 재디자인 |

> **Phase 1에서 Home 탭** = **개인 대시보드**로 채운다(6.5 참고). Phase 2가 되면 같은 탭 자리가 탐색 피드로 진화하므로 네비 구조 변경이 없다.

## 6. 화면별 상세 명세

### 6.1 가게 등록 화면 (Phase 1) ⭐ 핵심

**목적**: 최소 입력으로 빠르게 한 곳을 기록한다.

**🔑 핵심 플로우 — "가게 이름 검색"으로 시작**
한국 전용 + 카카오 장소검색이라, 등록의 시작은 **장소 검색**이다:
> **상단 검색창에 "스타벅스 강남" 입력 → 결과 리스트에서 탭 한 번 → 가게 이름·주소·좌표·(가능 시)카테고리가 자동 입력**

사용자는 거의 타이핑 없이 평가만 고르면 끝. 검색 없이 **직접 입력**하는 경로도 열어둔다(검색에 안 잡히는 신규 가게 등).

**필드**
| 구분 | 필드 | 필수 | 비고 |
|---|---|---|---|
| 필수 | 가게 이름 | ✅ | **장소 검색으로 자동 입력**(직접 입력도 가능) |
| 필수 | 평가 | ✅ | 4개 중 1개 선택 (큰 선택형 UI) |
| 선택 | 주소 | | **장소 검색 시 자동 채워짐**. 비었으면 검색/직접 입력 |
| 선택 | 이용 형태 | | 배달 / 포장 / 가게 식사 (다중 선택 가능) |
| 선택 | 카테고리 | | 12개 중 1개 (아래 카테고리 목록), 선호 카테고리 통계에 사용 |
| 선택 | 한줄 메모 | | "여기 파스타 짱" 같은 짧은 평가 사유 |
| 선택 | 방문일 | | 날짜 선택 (위시리스트는 비움) |
| 선택 | 가격대 | | **단계 기호 4단계** (₩ / ₩₩ / ₩₩₩ / ₩₩₩₩) |
| 선택 | 사진 | | 가게당 **최대 3장**, 자동 압축(WebP) |

**카테고리 목록 (12개, 1개 선택)**
한식 / 일식 / 중식 / 양식 / 아시안 / 카페·디저트 / 베이커리 / 패스트푸드·버거 / 고기·구이 / 해산물 / 술집·바 / 기타

**가격대 (단계 기호, 통화 무관)**
| 단계 | 표기 | 힌트(한국) |
|---|---|---|
| 저렴 | ₩ | ~1만원 |
| 보통 | ₩₩ | 1~2만원 |
| 비쌈 | ₩₩₩ | 2~4만원 |
| 고급 | ₩₩₩₩ | 4만원+ |
> 한국 전용이므로 통화기호 고민 없이 ₩ 단계로 통일. (₩ 개수로 가격대 표현, 구글/옐프 방식)

**상태/인터랙션**
- 평가에서 **"먹어보고 싶어요"** 선택 시 → 방문일/사진 입력은 비활성(또는 숨김) 가능. (위시리스트라 아직 안 먹었으므로)
- 저장 버튼은 필수 2개(이름·평가)가 채워질 때 활성화.
- 저장 즉시 로컬(Room)에 반영 → 리스트에 바로 보임 (오프라인 우선).

**디자인 톤**: 입력 단계가 부담스럽지 않게. 필수 2개만 채우면 끝나는 "빠른 기록" 경험.

### 6.1-B 외부 앱 공유로 등록 (Share to Register) — Phase 1

**진입**: 배민/네이버/카카오 등에서 **"공유 → StashMap"** (안드로이드 공유 시트에 StashMap 노출. 단, 시트 순서는 OS가 결정 — 강제 상위 노출 불가).

**처리 흐름 (graceful degradation)**
```
공유받은 텍스트에서 가게 이름 추출 시도
   ├─ ✅ 성공 + 단일/확실한 매칭(카카오 재검색)
   │     → 가게명·주소·좌표 자동 입력 (수정 가능)
   ├─ 🟡 이름은 추출됐으나 후보 여러 개
   │     → 후보 리스트 표시 → 사용자가 탭으로 선택
   └─ ❌ 아무것도 못 뽑음
         → 검색창 비운 채 등록 화면 → 사용자가 직접 검색
어느 경우든 마지막엔 평가만 고르면 등록 완료
```

**원칙**
- 자동 입력이어도 **항상 사용자가 수정 가능**.
- **절대 무음 자동 확정 금지** — 애매하면 후보를 보여주고 사용자 확인.
- 공유 링크 자체(내부 ID)로 좌표를 캐지 않음 → 추출한 **이름을 카카오로 재검색**해 위치 확보(약관 클린·안정적).

> ⚠️ **실측 필요**: 배민/요기요/쿠팡이츠 등 앱마다 공유 페이로드에 가게 이름이 들어오는지 다름. 각 앱에서 실제 공유해 페이로드를 확인해야 함(12장 미결 참고).

### 6.2 장소/주소 검색 화면 (Phase 1) — 카카오

**목적**: 앱 안에서 **가게(장소)를 검색**해 이름·주소·좌표를 한 번에 확보한다.

**방식 (카카오 로컬 — 키워드 장소검색)**
- 검색창에 **가게 이름 또는 주소** 입력 → 결과 리스트 표시.
- 결과 1건 탭 → **가게명·도로명주소·위경도·(가능 시)카테고리** 자동 채움 → 등록 화면으로 복귀.
- 검색에 없는 가게는 **주소만 검색**하거나 **직접 입력** 허용.

**화면 구성**
- 상단 검색 입력창 + 결과 리스트(장소명 / 주소 / 거리).
- (선택) 지도 미리보기에 핀.

**저장 데이터**: 위도, 경도, 도로명주소 텍스트, **시/도·시군구(필터용 컬럼)**.
> 등록 시 좌표 → 시/도·시군구를 추출·저장 → 지역 필터 쿼리를 싸게 만든다.

### 6.3 내가 등록한 가게 리스트 화면 = "맛집" 탭 (Phase 1) ⭐ 핵심

**상단: 통계 2x2 그리드**
```
┌──────────────┬──────────────┐
│ 😍 다시먹을래요 │ 😐 보통이에요  │
│      12      │      5       │
├──────────────┼──────────────┤
│ 🙅 다신안먹을래요│ 🔖 먹어보고싶어요│
│      3       │      8       │
└──────────────┴──────────────┘
```
- 4개 상태별 개수. 기존 `SMBaseCard` / `ActivityStatCards` 스타일 재활용 가능.
- 각 칸은 **탭하면 해당 상태로 리스트 필터링** 되면 좋음.

**하단: 가게 리스트 + 정렬/필터**
- 정렬: 최신순(등록순) / 다시 먹을래요 / 다신 안 먹을래요 등.
- 필터: 평가 상태별, (선택) 카테고리별.
- 리스트 아이템 1개: 가게명, 평가 뱃지(색/아이콘), 카테고리, 썸네일(있으면), 한줄메모, 거리/지역(선택).
- 리스트 썸네일은 **작은 썸네일만** 로드 (원본 X).

**빈 상태**: 등록된 가게가 없을 때 "첫 맛집을 기록해보세요" + 등록 CTA.

**FAB / 등록 진입**: 등록 화면(6.1)으로 가는 명확한 진입점(FAB 권장).

### 6.4 가게 상세 화면 (Phase 1)

**구성**
- 상단: 가게명 + 평가 뱃지(크게).
- 사진 영역: 등록한 사진들 (없으면 생략). 내 사진은 로컬에서 즉시 표시.
- 정보: 카테고리, 이용형태, 가격대, 방문일, 한줄메모.
- **지도 영역**: 위경도에 **카카오 지도 마커** 표시. **탭하면 카카오맵(또는 네이버맵) 앱으로 리다이렉트**(길찾기).
- 액션: 수정 / 삭제 / (위시리스트면) "방문 완료 → 평가하기".

### 6.5 Home 탭

같은 탭 자리가 단계에 따라 다른 내용을 담는다 (네비 구조 변경 없음).

#### 6.5-A Home 대시보드 (Phase 1)

**목적**: 앱을 열었을 때 반겨주는 "개인 홈". 내 활동을 한눈에.

**구성**
- 인사말 / 헤더 (예: "오늘은 어떤 맛집을 기록할까요?").
- **이번 주·이번 달 요약** (예: 이번 달 N곳 기록, 다시 갈 집 N곳).
- **최근 기록** 몇 개 (가로 스크롤 카드 등).
- **빠른 등록 CTA** (등록 화면 진입).
- (선택) 위시리스트 미리보기.

> Phase 2가 되면 이 화면이 탐색 피드로 진화하거나, 대시보드 + 피드를 함께 구성한다.

#### 6.5-B Home 탐색 피드 (Phase 2) ⭐ 소셜 핵심

**목적**: 다른 사람들의 **공개 기록**을 발견하고, 마음에 들면 **내 위시리스트로 담기**.

**필터/정렬**
- **지역 선택** (시/도 > 시군구/동 단위. 예: 서울 > 강남구).
- 정렬: **최신순 / 인기순**.
  - 인기순 = **담긴(stash) 횟수** 기준. (좋아요가 없으므로)
- **10개씩 페이지네이션** (스크롤 끝 → "더 보기" / 무한 스크롤).

**피드 아이템**
- 작성자(닉네임/아바타), 가게명, **평가 뱃지**, 썸네일(40KB 썸네일만), 한줄메모, 담긴 횟수.
- 액션: **담기(내 위시리스트로)**, **가게 집계 페이지로 이동**(6.6).

**소셜 범위 (명확히)**
- ✅ 둘러보기, 담기.
- ❌ 팔로우, 좋아요, 댓글, 알림. (의도적 제외 — 컨셉 단순화)

**모더레이션 (공개 UGC 필수)**
- 신고 / 차단 기능, 콘텐츠 정책. (앱스토어 심사 요구사항)

### 6.6 가게 집계 페이지 (Phase 2) ⭐ 컨셉의 완성

**목적**: 한 가게에 대한 **여러 사람의 정직한 평가를 합산**해 보여준다.
앱의 핵심 약속 — *"100명 중 78명이 다시 가겠다고 함"* — 을 실제로 구현하는 화면.

**묶는 키**: **카카오 장소 ID.** 같은 가게를 가리키는 여러 개인 기록을 하나의 canonical Place로 묶는다.

**핵심 표시 — 정직 비율**
```
OO국밥  (한식 · ₩₩)
─────────────────────────────
😍 다시 먹을래요   ████████░░  78%
😐 보통이에요      ██░░░░░░░░  15%
🙅 다신 안먹을래요  █░░░░░░░░░   7%
                    평가한 사람 45명
```

- 3단계 분포 바(긍정/중립/부정) + **표본 수(N)** 를 항상 함께 노출.
- 위시리스트(담은 수)는 별도 표기.

**신뢰 장치 (조작 방지 앱이므로 필수)**
- **표본 수(N)를 반드시 노출.** N이 작으면(예: <5명) % 대신 *"아직 평가가 적어요 (2명)"* 로 표시 → "1명 중 100%" 같은 오해 차단.
- **1인 1평가 / 가게** (계정 기반이라 강제 가능) → 다중 계정 조작 방지.

**구성**
- 상단: 가게명, 카테고리, 가격대, 카카오 지도 마커(탭 → 길찾기).
- 정직 비율 분포 + 표본 수 + 담은 수.
- 공개 기록 리스트: 사람들의 한줄메모·사진·평가 (10개씩 페이지네이션).
- 액션: **위시리스트에 담기**, **내 평가 남기기/보기**(등록 화면 연결).

**진입 경로**
- Home 탐색 피드 아이템 → 집계 페이지.
- 검색 결과 → 집계 페이지.
- 내 기록 상세 → "이 가게의 다른 평가 보기".

> ⚠️ 직접 입력(카카오 검색 미매칭)으로 등록돼 **장소 ID가 없는 기록은 집계 불가** → 개인 기록으로만 남음.

## 7. 데이터 모델 (디자이너 참고용 — 화면에 등장하는 필드)

**2단계 구조**: 개인 기록(Record) + 집계 가게(Place). **카카오 장소 ID**가 둘을 잇는다.

**Record (개인 가게 기록)** — Phase 1부터
- id, 이름, **평가(4상태 enum)**, 카테고리, 이용형태(set), 가격대(1~4), 한줄메모, 방문일, 생성일
- 위도, 경도, 도로명주소, **시/도, 시군구**, **카카오 장소 ID(집계 연결 키)**
- 사진들(로컬 URI + 서버 URL), 썸네일 URL
- (Phase 2) 작성자 id, 공개 여부, 동기화 상태(PENDING/SYNCED)

**Place (집계 가게)** — Phase 2, **카카오 장소 ID가 식별자**
- 카카오 장소 ID, 이름, 카테고리, 좌표, 주소
- 집계값: 평가 3종 카운트(다시/보통/안먹), 담은 수, **총 평가자 수(N)**
- 집계는 서버(Supabase)에서 공개 Record들로 계산(뷰 또는 카운터 컬럼)

> Phase 1에서도 Record에 **카카오 장소 ID를 저장**해두면, Phase 2에서 마이그레이션 없이 바로 집계 가능. (장소 ID 없는 직접입력 기록은 집계 제외)

## 8. 기술 제약 (디자인에 영향 주는 것만)

- **오프라인 우선**: 등록은 항상 즉시 로컬 반영. 동기화는 백그라운드.
- **사진**: 자동 압축(WebP), **가게당 장수 제한**, 리스트는 썸네일만. → 디자인 시 사진 개수 상한과 썸네일/원본 구분 고려.
- **탐색 피드**: 한 번에 10개. → "더 보기" 또는 무한 스크롤 UI 필요.
- **지도/장소**: **카카오** 기반. 등록은 장소 검색으로 자동 채움. 상세는 카카오 지도 마커, 길찾기는 카카오맵/네이버맵 앱 리다이렉트.

## 9. 디자인 시스템

> **중요**: 색상과 타입 스케일(폰트 크기)은 **새 디자인 시스템 기준**으로 자유롭게 설계한다.
> 이 repo의 기존 색/크기는 **교체 예정**이므로 거기에 맞출 필요 없음.
> 단, **폰트 패밀리는 Pretendard 유지**.

**디자인 시 지켜야 할 것**
- **폰트**: Pretendard (유지). 타입 스케일(크기/굵기)은 새 시스템 기준.
- **색상**: 새 시스템 기준. **라이트/다크 모드 둘 다** 정의 필요.
- **다국어(한·영)** 전제 — 텍스트 길이 변화를 견디는 레이아웃.
- **네비**: 바텀 3탭(Home / 맛집 / 프로필) 구조 유지.

**산출물로 함께 받을 것 (구현 연결용)**
- 색상 토큰 전체 (hex, 라이트/다크 각각)
- 타입 스케일 스펙 (스타일명 / 크기 / 행간 / 굵기)
- 평가 4상태의 색·아이콘 정의

**참고 — 기존 repo의 토큰 구조** (새 값을 이 구조에 매핑하면 구현이 깔끔):
- 색상: `StashMapColors` (색상군 × 4단계 Light1/Light2/Dark1/Dark2 + bgColor/baseColor)
- 타이포: `TextStyleEnum` (Title1~4, Body1~3, HeadLine0~3, Caption, OverLine 등)
- 컴포넌트: `SMTopBar`, `SMBaseCard`, `SMSettingItem`, `HDivider`

> 디자인 확정 후, 이 repo의 `Color.kt`/`LightColor.kt`/`DarkColor.kt`/`Type.kt`를 새 시스템으로 갱신하는 작업이 별도로 필요하다.

## 12. 확정된 결정 & 남은 미결

**확정**
- **한국 전용** 서비스. 지도·장소·로그인 모두 **카카오** 우선.
- 등록은 **카카오 장소 검색**으로 이름·주소·좌표 자동 채움(직접 입력도 가능).
- Phase 1 Home 탭 = **개인 대시보드** (6.5-A).
- 가게당 사진 **최대 3장**, WebP 자동 압축.
- 가격대 = **₩ 단계 4단계** (₩ / ₩₩ / ₩₩₩ / ₩₩₩₩). 한국 전용이라 통화 고민 없음.
- 카테고리 = **12개** (한식/일식/중식/양식/아시안/카페·디저트/베이커리/패스트푸드·버거/고기·구이/해산물/술집·바/기타).
- 프로필 = **재디자인 대상** (완료 아님).
- **가게 집계 페이지 채택(6.6)** — 카카오 장소 ID로 여러 사람 평가를 합산해 정직 비율 표시(Phase 2). 데이터 모델은 Record+Place 2단계. 표본 수(N) 항상 노출, 1인 1평가.

**남은 미결**
- 평가 4상태의 최종 아이콘/색 (PRD 4장 제안 기준) — 디자이너 확정.
- 대시보드 위젯 구성 디테일 — 디자이너 확정.
- **배달앱별 공유 페이로드 실측** (배민/요기요/쿠팡이츠 — 공유 시 가게 이름이 텍스트로 들어오는지). 개발 단계에서 검증 → 6.1-B 자동입력 가능 범위 결정.
- 집계 % 노출 **최소 표본 수 임계값**(예: 5명 미만이면 % 숨김) 확정.
